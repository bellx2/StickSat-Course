# 00. はじめに（セットアップとリセット）

## 1. ボードを用意する

- FlatSat-Geek（書き込み済みのボード。[BOOTH で頒布](https://bellx2.booth.pm/items/9193868)）をそのまま使う。
- 自分で書き込む場合は、[FlatSat-Geek のリリース](https://github.com/bellx2/FlatSat-Geek/releases) の UF2（ボードに書き込むファームウェアのファイル）を、BOOT ボタンを押しながら USB 接続して現れるドライブにコピーする。
  - ステップ 6 で使う位置の上書き命令（`GPS_OVERRIDE`）は、RP2350-GEEK 向けのビルドに含まれている。
  - ステップ 9 でスコアボードの `AES CFG` が点くのは、v1.2.1 以降。それより前のバージョンでは点かない（攻撃そのものは成立する）。

## 2. PC を用意する

使うものは 3 つです。

- このリポジトリ: 攻撃スクリプト（`attacks/`）。Python の環境は [uv](https://docs.astral.sh/uv/) で作る。
- [JP-Bootcamp](https://github.com/bellx2/JP-Bootcamp): センサー（Space IDS）。
- [FlatSat-Geek](https://github.com/bellx2/FlatSat-Geek): ファームウェアのソース。コードを読むステップで使う。

センサーがなくても、ボード単体で演習を進められます。その場合は JP-Bootcamp の用意を飛ばし、§2 の「攻撃スクリプトの環境（uv）」と §6 を読んでください。

### リポジトリを取得する

使うリポジトリは、1 つの作業用フォルダの中に**並べて**置きます。手順書と AI への指示（`AGENTS.md`）は、この並びを前提に `../JP-Bootcamp` のような場所で書いてあります。

    作業用フォルダ/
      FlatSat-Geek-Course/   このリポジトリ
      JP-Bootcamp/           センサー（使わないなら要らない）
      FlatSat-Geek/          ファームウェアのソース（コードを読むステップで使う）

作業用フォルダで、次を実行します。

    git clone https://github.com/bellx2/FlatSat-Geek-Course.git
    git clone https://github.com/bellx2/JP-Bootcamp.git
    git clone https://github.com/bellx2/FlatSat-Geek.git

- センサーを使わない場合は、2 行目（JP-Bootcamp）を飛ばしてよい。
- すでにこのリポジトリだけを取得している場合は、このリポジトリのフォルダで `git clone https://github.com/bellx2/JP-Bootcamp.git ../JP-Bootcamp` のように、置き場所を `../` で指定して取得する。

### JP-Bootcamp の環境を作る

まず JP-Bootcamp を用意します。詳しい手順と、つまずいたときの説明は、JP-Bootcamp の `docs/01-mac-setup.md` と `docs/01-ubuntu-setup.md` にあります。

#### macOS

Homebrew と mise（Python などの開発ツールの版をそろえる道具）が入っていて、シェルで mise が有効になっている場合は、作業用フォルダで次を実行します。

    cd JP-Bootcamp
    mise trust && mise install
    uv pip install -r requirements.txt

- 入っていない場合は、JP-Bootcamp の `docs/01-mac-setup.md` の §1〜§2 から始める。
- macOS では、シリアルポートを開くための追加の設定は要らない。

#### Ubuntu

作業用フォルダで、次を実行します。

    cd JP-Bootcamp
    ./install.sh

- そのあと、**一度ログアウトして再ログイン**する（`install.sh` が、ユーザーを `dialout` グループに追加するため。`dialout` は、Ubuntu でシリアルポートを開ける権限を持つグループ）。
- `install.sh` の中身を読んでから実行したい場合は、JP-Bootcamp の `docs/01-ubuntu-setup.md` に同じ処理が手作業の手順として書いてある。

### 攻撃スクリプトの環境（uv）

このリポジトリのフォルダで、次を実行します。

    uv sync

- 必要なライブラリ（pyserial と pycryptodome）が、このリポジトリの `.venv` に入る。依存は `pyproject.toml` に書いてある。
- `uv` が見つからない場合は、先に uv を入れる（macOS は `brew install uv`、Ubuntu は uv の公式ドキュメントのインストール手順）。

## 3. 動作確認

### ソフトウェア（ボードをつながずに）

JP-Bootcamp のフォルダで、次を実行します。

    cd ids && python -m pytest tests/ -q

`passed` と出れば、インストールは正常です。

### ボードをつないで

1. ボードを PC の USB ポートに挿す。USB ハブより、PC 本体のポートに直接挿す方が確実。
2. ボードの画面が点き、起動画面に `WAIT USB CONSOLE` と表示されることを確かめる。
   - これは、PC のプログラムがボードのコンソール（ログを出す側のポート）を開くのを待っている表示で、故障ではない。そのまま次の手順へ進む。
   - 待っている間も、BOOT ボタンを短く押すと画面のページが切り替わる。
3. センサーから、ボードが見えることを確かめる。

       cd ids && ./run.sh boards

   このコマンドがボードのポートを開くと、起動画面の表示が `SENSORS INIT`、`READY` と進み、ステータス画面に切り替わる。
   1 枚のボードが 2 つのポートとして表示されるのは、正しい動作。
   何も表示されない場合は、USB ケーブルが充電専用である可能性が高い。データ通信のできるケーブルに替える。

### センサーを起動する

演習の間、センサー（Space IDS）を起動したままにします。ターミナルを 1 つ使います。

    cd JP-Bootcamp/ids
    ./run.sh run

- センサーのコンソールは http://127.0.0.1:5011 。各ステップで、アラートをここで確かめる。
- 攻撃スクリプトは別のターミナルで、このリポジトリの `attacks/` から実行する。必ず `FLATSAT_HOST=1` を付ける（付けないとセンサーを通らず、アラートが出ない）。
- 地上局コンソール（C3、http://127.0.0.1:8000）は、この演習では必須ではない。使う場合は、JP-Bootcamp の `docs/03-running-the-bench.md` を参照する。

### 攻撃スクリプトのターミナルを用意する

別のターミナルで、このリポジトリの `attacks/` に移動します。

    cd FlatSat-Geek-Course/attacks

- 各ステップで `attacks/` のスクリプトを実行するときは、このターミナルを使う。
- スクリプトは `uv run python ...` で実行する。`uv run` が §2 で作った環境を自動で使う。
- `No module named 'serial'` と出る場合は、`uv run` を付け忘れている。または §2 の `uv sync` をしていない。

## 4. ステップの合間のリセット

いくつかのステップは**意図的に**ボードの状態を残します（位置、地上局モード、暗号の設定、USB デバッグなど）。
前のステップの影響で、次のステップが失敗しないよう、**ステップの合間にリセット**してください。

### 方法 1: リセット用のスクリプト（おすすめ）

このリポジトリの `attacks/` で、次を実行します。

    FLATSAT_HOST=1 uv run python lib/reset_bench.py

位置を東京に戻し、地上局モードをオフ、セキュアリンクをオン、USB デバッグをオフにします。最後に `bench clean` と出れば成功です。
位置は「上書き」で東京に戻すため、リセット後も画面に `OVR` が出ます。

このスクリプトは**スラスターの出力、ビーコンの間隔、ミッションモードは戻しません**。ステップ 1（命令の洗い出し）のあとや、スラスターを 0 に戻したいときは、方法 2 を使ってください。

### 方法 2: USB の抜き挿し

USB ケーブルを抜き、3 秒待って挿し直します。約 8 秒で戻ります。

- ファームウェアは状態をボードに保存していません。抜き挿しで、すべての状態が起動時の値に戻ります（セキュアリンクはオン、地上局モードと USB デバッグはオフ、位置は東京、スラスターは 0）。
- 起動時の位置は「東京への上書き」として設定されるため、画面には最初から `OVR` が出ます。
- **画面のスコアボードも消えます**。 進み具合を残したい場合は、方法 1 を使う。
- スクリプトがボードと通信できなくなったとき（`the board did not answer` など）も、この方法で復旧できる。

### ボードが再起動するステップ（4 と 10）

- ステップ 4（取り消しのきかないコマンド）とステップ 10（長さ計算のアンダーフロー）は、ボードを再起動させます。再起動すると、状態は起動時の値に戻ります（方法 2 と同じ）。そのあとのリセットは要りません。
- 再起動すると、画面のスコアボードの記録も消えます。
- センサー経由で実行している場合、ボードが再起動している間、センサーは約 30 秒までポートを開き直そうとします。ボードが戻れば、センサーはそのまま使えます。30 秒たっても戻らない場合は、USB ケーブルを抜き挿しし、センサーを起動し直してください。

## 5. よくある詰まりどころ

- **アラートが出ない** → `FLATSAT_HOST=1` を付け忘れている。または、センサーを起動していない。
- **`FLATSAT_HOST=1` を付けると `Connection refused` などで止まる** → センサーを起動していない。センサーなしで進めるなら、`FLATSAT_HOST=1` を外す（§6）。
- **何も起きない、拒否される** → ボードが前のステップの状態のまま。リセットする。
- **ステップ 1 や 8 のあと、暗号化した命令がおかしな結果になる** → USB デバッグがオンになったまま（ステップ 1 はスイープの副作用、ステップ 8 は攻撃そのもの）。リセットする。
- **ボードが応答しない** → USB ケーブルを抜いて 3 秒待ち、挿し直す（約 8 秒で戻る）。
- **センサーが `Could not exclusively lock port` で止まる** → ほかのプログラムがボードのポートを開いている。C3 などを先に止めてから、センサーを起動する。

## 6. センサーなしで進める（ボード単体）

センサー（Space IDS）を用意しなくても、攻撃そのものはすべて成立します。観察できなくなるのは**センサーのアラートだけ**です。ボードの返事と画面の変化は、センサーありと同じように観察できます。

### 用意するもの

- ボード、PC、このリポジトリ（§2 の「攻撃スクリプトの環境（uv）」まで）。JP-Bootcamp は要らない。

### 実行のしかた

カードと §4 のコマンドから、**`FLATSAT_HOST=1` を外して**実行します。

    uv run python 00_recon_apid_enum/00_recon_apid_enum_usb.py
    uv run python lib/reset_bench.py

- `FLATSAT_HOST=1` を外すと、スクリプトはセンサーを通らず、USB でボードに直接つなぐ。`tools/` のスクリプトも同じ。
- 最初の動作確認にはリセット用のスクリプトを使う。最後に `bench clean` と出れば、ボードと通信できている。
- 挿した直後の画面は `WAIT USB CONSOLE` のまま止まっている（§3 の「ボードをつないで」）。センサーなしでは、このスクリプトがポートを開いた時点で起動が進む。
- センサーや地上局コンソール（C3）を起動したままにしない。起動していると、それらがボードのポートを独占するため、スクリプトがボードを見つけられない（`no FlatSat answered a PING` と出る）。

### カードの読み替え

- 「センサー経由」と書かれた手順は、`FLATSAT_HOST=1` を外して実行する。
- 「予想してみよう」のセンサーに関する問い（ステップ 1・4・5・6・8・9・10 の Q3）は、そのまま予想として書いておく。
- 「観察しよう」のセンサー（IDS）のコンソールの項目は、飛ばす。
- 代わりに、解説の「センサーの見方」「センサーが気付けない理由」などを読み、自分の予想と比べる。

### 注意

- ステップ 6（位置のなりすまし）とステップ 9（暗号のダウングレード）は、センサーが「何に気付き、何に気付けないか」が学びの中心の一つです。センサーなしでは、この部分を**実機で確かめられません**。
- そのため、振り返りでは、センサーについて分かったことを「AI が言っただけのこと」（または「カードに書いてあっただけのこと」）の欄に書く。「自分で確認できたこと」には入れない。
- あとからセンサーを用意した場合は、ステップ 6 と 9 だけでも、センサーありでやり直すとよい。
