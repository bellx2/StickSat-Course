# AI と一緒に学ぶ

この演習は AI アシスタントを使うことを歓迎します。ただし、**AI に答えを出してもらうだけ**では、学んだことになりません。
AI には「家庭教師」になってもらいます。そのための指示は、リポジトリの `AGENTS.md` に書いてあります。この文書では、AI の種類ごとに `AGENTS.md` を読ませる方法と、ステップの進め方を説明します。

## 1. AI の種類を選ぶ

AI は、大きく 3 種類に分かれます。どれを使っても演習はできますが、できることが違います。

| 種類 | 例 | リポジトリのファイルを読めるか | ボードに命令を送れるか |
|---|---|---|---|
| 手元で動くエージェント（PC の上でファイルを読み、コマンドを実行する AI） | Codex（Codex CLI）、Claude Code | 読める | 送れる（実行を許可した場合） |
| チャット | ChatGPT、claude.ai、Gemini などの Web やアプリ | 読めない（自分で貼る） | 送れない |
| クラウドで動くエージェント | Web から依頼して、クラウドの環境で作業する AI | 読める（GitHub などに置いた場合） | 送れない（ボードは手元の USB にある） |

- 初めての人には、**コマンドは自分で実行し、AI には相談だけをする**使い方をすすめます。どの種類の AI でもできます。ボードの返事と画面の変化を自分で見ることが、この演習の中心だからです。
- 手元で動くエージェントは、カードのコマンドを代わりに実行させることもできます。その場合も、実行の前に**コマンドの中身を自分で読んでから許可**してください（§6）。
- クラウドで動くエージェントは、手元の USB のボードに届きません。この演習には向きません。

## 2. 始める前の用意（共通）

1. このリポジトリを用意し、[docs/00-start.md](00-start.md) の手順で、ボードと通信できることを確かめる。
2. ファームウェアのソースを手元に置く。カードの「解説」「直し方」「ヒント」に出てくる `Firmware/worker.cpp` などは、[FlatSat-Geek](https://github.com/bellx2/FlatSat-Geek) のリポジトリにあります。このリポジトリと同じ階層に置くと、AI に場所を伝えやすくなります。

       # このリポジトリの 1 つ上のフォルダへ移ってから、取得する
       cd ..
       git clone https://github.com/bellx2/FlatSat-Geek.git

   置いたあとは、`../FlatSat-Geek/Firmware/worker.cpp` のように、このリポジトリから見た場所で AI に伝えます。
3. 記録用のノート（紙でも、テキストファイルでもよい）を用意する。予想、観察、振り返りを書きます。

## 3. Codex（Codex CLI）で進める

Codex は、リポジトリの `AGENTS.md` を自動で読みます。特別な設定は要りません。

1. インストールとログインは、OpenAI の公式の案内に従う。
2. このリポジトリのフォルダで起動する。

       cd FlatSat-Geek-Course
       codex

3. 最初に、次のように頼む（§7 の「始めるとき」）。

   > AGENTS.md に従って、家庭教師として振る舞ってください。今から stages/01-recon.md を始めます。

4. コマンドの実行は、**実行の前に承認を求める設定**のまま使う。Codex がコマンドを実行しようとしたら、何を送るコマンドかを読んでから承認する。
5. ファームウェアのコードを読ませるときは、場所を伝える（例: 「`../FlatSat-Geek/Firmware/worker.cpp` の `commandApidHandler` を一緒に読んでください」）。

## 4. Claude Code で進める

Claude Code は、`AGENTS.md` ではなく `CLAUDE.md` を読みます。このリポジトリの `CLAUDE.md` には、`AGENTS.md` を読み込む指示（`@AGENTS.md`）だけが書いてあります。そのため、Codex と同じ指示で動きます。

1. インストールとログインは、Anthropic の公式の案内に従う。
2. このリポジトリのフォルダで起動する。

       cd FlatSat-Geek-Course
       claude

3. 最初に、次のように頼む（§7 の「始めるとき」）。

   > 家庭教師として教えてください。今から stages/01-recon.md を始めます。

4. Claude Code は、コマンドを実行する前に許可を求めます。何を送るコマンドかを読んでから許可する。「今後は確認しない」のような、まとめて許可する選択肢は選ばない。
5. ファームウェアのコードを読ませるときは、`/add-dir ../FlatSat-Geek` でフォルダを追加してから、場所を伝える。

## 5. ChatGPT・claude.ai などのチャットで進める

チャットの AI は、リポジトリもボードも見えません。必要なものを、**自分で貼って**渡します。

1. 新しい会話を始め、最初に `AGENTS.md` の全文を貼り、次のように頼む。

   > 次の文章は、この会話でのあなたへの指示です。この指示に従って、家庭教師として振る舞ってください。
   > （ここに AGENTS.md の全文）

2. 続けて、今から進めるステップのカード（`stages/` の `.md`）の全文を貼る。
3. 自分でコマンドを実行し、出力を貼る。出力に `===` の見出しがあるときは、**見出し 1 つ分ずつ**貼り、その区切りの問いに答えてから次を貼る。
4. コードを読む課題では、ファイル全体ではなく、カードに出てくる関数（`commandApidHandler` の該当する分岐など）を探して、その部分だけを貼る。
5. AI がスクリプトの変更を書いてきたら、変更点を自分で読み、説明できるようになってから保存する。保存するのは、元のファイルではなく、コピーしたファイル（`my_09.py` など）にする。

- プロジェクト機能（会話をまとめ、共通の指示やファイルを置ける機能）がある場合は、`AGENTS.md` を指示として、カードをファイルとして置くと、会話ごとに貼り直さずに済みます。
- 会話が長くなると、AI が最初の指示を守らなくなることがあります。答えを先に言うようになったら、ステップごとに新しい会話を始め、`AGENTS.md` から貼り直してください。

## 6. エージェントにコマンドを実行させるときの注意

手元で動くエージェント（Codex、Claude Code）にカードのコマンドを実行させる場合は、次を守ってください。`AGENTS.md` にも同じことが書いてありますが、最後に許可するのは自分です。

- **1 回に 1 つのコマンド**を許可する。攻撃のスクリプトを続けて実行させたり、ループで回させたりしない（[docs/00-start.md](00-start.md) の注意）。
- **ボードが再起動するステップ**（ステップ 4 と 10）は、実行の前に、何が起きるかと復旧方法（USB の抜き挿し）を AI に説明させ、自分で納得してから許可する。ステップ 4 のスクリプトは確認の入力を求めるので、自分の端末で実行するほうが分かりやすい。
- **ステップ 8** の元のスクリプトは、そのままでは失敗します。失敗の理由を自分で調べるのが課題なので、AI に先に直させない。
- エージェントが出力を要約して「成功しました」とだけ言ったら、出力そのものを見せてもらう。カードの問いは、出力の行を見て答えるように作ってあります。
- スクリプトやファームウェアの変更は、**差分を自分で読んでから**採用する。

## 7. ステップの進め方と頼み方の例

AI の種類にかかわらず、各ステップは次の順に進めます。`>` の行は、AI への頼み方の例です。

### 始めるとき

> 今から stages/05-flash-read.md を始めます。答えは先に言わず、まず「予想してみよう」の問いについて、私の予想を聞いてください。

### 予想を話す

カードの Q1〜Q3 に、自分の予想と、そう考えた理由を書いて伝えます。AI に正解を聞くのではなく、**理由に足りない点**を聞きます。

> Q1 は「受け付ける」と予想しました。理由は、ステップ 3 で送り主を確かめていなかったからです。正解は言わずに、この理由で見落としていそうな点があれば、問いの形で教えてください。

### 実行する前

> この操作で、ボードに何が起きますか？ 戻らなくなったときの復旧方法も教えてください。

### 出力を読む

出力は、`===` の見出し 1 つ分ずつ読みます。

> 出力の「=== 1. ...」の部分です（ここに貼る）。この区切りの問いに対する私の答えは「…」です。答えを言わずに、見るべき行を指してください。

### 詰まったとき

> ヒントを 1 つだけください。カードのヒント 1 から順にお願いします。

いきなり答えを聞かず、ヒントは 1 → 2 → 3 の順に 1 つずつもらいます。

### 解説を読むとき

先に自分の言葉で説明してから、AI に確かめてもらいます。

> なぜこの攻撃が成立したかを、自分の言葉で説明します（ここに書く）。抜けている点や間違っている点を指摘してください。

### 直し方を考えるとき

> ファームウェアのどこを、どう直せばこの攻撃を防げるか、私の案を書きます（ここに書く）。この案で防げない攻撃の仕方があれば、問いの形で教えてください。

パッチ（ファームウェアの変更）を AI と書いた場合は、§8 の手順で実機で確かめます。

### 振り返り

> 今日のステップで、「自分で確認できたこと」と「AI が言っただけのこと」を分けて書きました（ここに書く）。分け方が間違っている所があれば指摘してください。

カードの「振り返り」の欄をノートに写して書きます。センサーなしで進めた場合は、センサーについて分かったことを「AI が言っただけのこと」の側に書きます（[docs/00-start.md](00-start.md) の §6）。

## 8. 直したファームウェアを実機で確かめる

カードの「直し方」は、パッチを書いて、**実機で攻撃が通らなくなること**を確かめるところまでが目標です。

1. FlatSat-Geek のリポジトリで、AI と一緒に書いたパッチを当てる。変更は 1 か所ずつにし、差分を自分で読む。
2. ファームウェアをビルドし、ボードに書き込む。ビルドに必要なもの（PlatformIO）とビルドの手順は、FlatSat-Geek の README（日本語版は `README_ja.md`）のビルドの説明にあります。
3. 同じ攻撃のスクリプトを実行し、拒否されること（または、ボードが落ちないこと）を確かめる。
4. 終わったら、リリース版の UF2 を書き込み直して、元のファームウェアに戻す（[docs/00-start.md](00-start.md) の §1）。ほかのステップは、元のファームウェアを前提にしています。

## 9. 気をつけること

- AI の書いたスクリプトや説明は、間違うことがあります。**自分で確認できたこと**と、**AI が言っただけのこと**を分けてメモしてください。ステップ 8 では、スクリプト自身の説明が外れる例を体験します。
- ボードを固まらせる操作（ファザー: でたらめな入力を大量に送って異常を探す攻撃など）は、実行前に、何が起きるかと復旧方法を AI に聞いてください。
- 攻撃の対象は**自分が所有するボードだけ**です。AI が、ほかの機器や実在する衛星、無線を使う方法に話を広げたら、そこで止めてください。
