## ファームウェアで修正が必要だった2点

**`03` はUSB経由では存在しませんでした。** 本来の位置攻撃は無線経由でu-bloxの受信機に対して行うもので、
別のハードウェアを攻撃するためケーブル版はありません。リポジトリのスクリプトはデバッグビルド
`firmware/gps-debug-demo/` の `GPS_OVERRIDE`（APID `0x14`）を指していましたが、
**そのディレクトリはディスク上のどこにも存在しません**。それがないと演習 `2.3` は実行できませんでした。

現在 `GPS_OVERRIDE` は**講座用ビルド**に専用のフラグ（`FLATSAT_GPS_OVERRIDE`）の下で実装されており、
公開ファームウェアには含まれません。教訓は変わらず、もともと無線に関するものではありませんでした。
航法と認可は便利だからという理由で結び付けられ、その結果、誤った位置が権限になってしまうということです。

**`06` は演習 `2.5` の可逆な代替です。** RESETCは再起動を行い、再起動は自然に元に戻ります。
ここにあるスクリプトはどれも不可逆なコマンドを送りません。演習で測るもの、つまり検知できることと手遅れであることの間の差は、
再起動でも忠実に示せます。

## `lib/flatsat.py`

独自のトランスポートです。PINGによるポートの探索、`0xAA 0x55 <len> <SPP>` のフレーミング、
ファームウェアのAES-128-ECBラッパー、`mission.h` のAPIDを持っています。

**IDSとはコーデックを意図的に共有していません。** 攻撃者のパーサーでパースする検知器は、
そのパーサーが誤って解釈するフレームを捕まえられません。

書き直す人が引っかかる点が1つあります。`FLASH_READ` は**同じ6オクテットに2つのエンディアン**を持っており、
オフセットはリトルエンディアン、アンロックタグはビッグエンディアンです。また、1オクテットの平文コマンドには付随するオクテットが必要です。
ファームウェアは長さフィールドがゼロより大きい場合にしかペイロードをコピーしないためです。

## 状態

2026年11月7日に、センサーをインラインに置き、その上で地上局コンソールを動かした状態で、
ボード `fsat-200052E9` に対して10種類すべてを実行しました。アラートは116件、発火したルールは11種類、
通常のトラフィックではゼロでした。

**10種類を連続で実行しないでください。** `01` はファザーなのでボードが応答しなくなることがあり、`06` はボードを再起動します。
1つずつ実行し、演習の合間には `lib/reset_bench.py` を使ってください。

**`00` はUSBデバッグをオンにします。** スイープは `DEBUG_CONFIG` も他の識別子と同様に探索するため、
`mission_ctx.usbDebugEnabled` が設定されます。これが設定されている間、ボードはセキュアリンクを迂回し（`worker.cpp:707`）、
暗号化されたペイロードを平文として読みます。そのため `08` はウィンドウIDが完全に正しいのに `FLASH WINDOW LOCKED` を報告し、
位置のテレメトリはあり得ない値として読まれます。
`reset_bench.py` がこれを解除します。リセット自体が `gate-exemption-chain` を発火させないよう、`GS_MODE` の後、最後に解除します。

## どのFlatSatでも、Ubuntuでも

デバイスパスを持つスクリプトはもうありません。ポートはノードの名前ではなくボードの**USB識別子**（`239a:cafe`）で見つけるため、
同じ呼び出しがUbuntuの `/dev/ttyACM*` でもmacOSの `/dev/cu.usbmodem*` でも動き、どちらの名前もコードには現れません。

```sh
uv run python 00_recon_apid_enum/00_recon_apid_enum_usb.py      # 接続されているボードをどれでも使う

export FLATSAT_SERIAL=fsat-200052E2                       # 複数接続している場合
export FLATSAT_PORT=/dev/ttyACM1                          # どうしても必要なら手動で指定
```

どちらの変数も `lib/flatsat.py` が読むので、どの攻撃にも新しいフラグを追加することなく、10種類すべてで使えます。

**ボードは同じシリアル番号を持つ2つのCDCインターフェイスを公開しており**、どちらがフレームを運ぶかは抜き差しのたびに変わり得ます。
ディスカバリーは列挙の順序を信用するのではなく、探索して応答した方を使います。
`ids/run.sh boards` は、どちらがコンソールでどちらがフレームを運ぶかを示す列付きでそれらを一覧表示します。

### 攻撃をセンサー経由で送る

```sh
FLATSAT_HOST=1 uv run python 00_recon_apid_enum/00_recon_apid_enum_usb.py
```

`FLATSAT_HOST=1` は通信をボードに直接ではなくセンサー経由で送るので、行ったことはすべて途中で分類されます。
すべての演習でこのモードを使います。これがないとセンサーは攻撃を一切見ず、アラート一覧が空になって、ルールが機能していないように見えます。

### Ubuntuで、初回実行の前に

```sh
sudo usermod -aG dialout "$USER"     # その後、ログアウトして再ログインする
pip3 install pyserial pycryptodomex
```

`dialout` グループに入っていないと、ポートは存在しても開けません。エラーはそのことをそのまま伝えます。
